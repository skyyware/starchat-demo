Run the actual application through Stage 0.2 on PHP 8.4. composer.json requires php "^8.4", skyyware/stage "^0.2", config.allow-plugins false, no repositories override and scripts.start "@php -S 127.0.0.1:8080 -t public public/index.php". Keep public/index.php identical to the configured starter except whitespace. End app.php with a direct top-level return new \Stage\Http\Application(...), using that fully qualified name.

Use Stage\Http\Route::get(path, handler) or new Stage\Http\Route(method, path, handler). A handler receives one Request and returns a Response. Request exposes body and query as strings: parse_str($request->body, $form) decodes forms; parse query the same way. Route /devices/{id} supplies $request->parameters['id']. There is no form() method or Route::post(). Response::json() returns JSON; new Response($html, 200, ['content-type' => 'text/html; charset=utf-8']) returns HTML; new Response('', 303, ['location' => '/']) redirects. Use isolated checks through Application::handle(new Request(...)). An incompatible requirement such as Python-only receives out_of_scope with no files.

This installation requests visual design for human-facing apps. Prefer a shared server-rendered layout, reusable forms, native controls and concise local CSS. Related tasks can share one clear work screen. Aim for around 10 KiB of application files where feasible. Styling takes precedence over the generic 6 KiB target; preserve the 32 KiB limit and handoff margin. Use readable system fonts, a restrained palette, consistent spacing and a clear primary action. No external assets, trackers, UI dependencies or fake user records. A static mockup or bare unstyled form is insufficient. Explicit API-only requests need no UI.

Complete the useful loop: helpful empty state, labeled input, validation, saved result and its next action, including agreed editing and deletion. Use semantic landmarks, visible focus, good contrast and comfortable touch targets. Adapt from phones to desktop without overflow; keep long names and notes readable. Never convey status by color alone. Document desktop/phone checks. Local tests use isolated data, never a user's store.

Escape output, validate input, store data outside public/ and protect state-changing requests. Deferred accounts, households or invitations remain later work. If required now, implement authorization and isolation, not just a household selector. Invitations need expiry and single use; no email without a configured service. Do not replace agreed sharing with a local app. Ask one focused question if a missing access rule prevents implementation.
